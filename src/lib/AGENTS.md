# src/lib rules
- Bài 11.1 scheduled hand-out stores the future moment in classrooms.started_at and every cube read/submit checks assignmentStarted on the server clock, so release happens exactly on time without a timer job and other lessons are untouched.
- The teacher's screen in timed Bài 12 parts shows sharedQuestion (slowest team's reconciled step), selected only when it changes after arrival (useFollowSharedQuestion ignores the value present on mount), so entering a part with Enter/Backspace opens the slide navigation chose, manual keys still work and team clocks stay independent.
- Step keys map through pure stepKeyAction (→ = Enter, ← = Backspace) and on-screen arrows (SlideArrows) dispatch the same key event, so buttons and keys share one handler and never drift apart.
- The parallel case keeps d at a fixed PARALLEL_HEIGHT with a horizontal direction (slide + turn about a vertical axis only), so the distance from d to the plane never changes.
- Luyện tập 3 (part 6, AI NHANH HƠN) reuses the timed-step Track on its own quiz_* columns; question data, race ranking/bar shares (raceStandings, raceBar) and the static textbook figures (quiz-figures.ts, parallel-projection points with derived midpoints/centroids drawn as SVG) stay in pure modules; lane reordering animates by FLIP on offsetTop so it never changes ranking.
- Hoạt động 2 models are framed by pure fitCaseView (geometry-fit.ts) from the live frame shape: camera and target slide together and only the field of view narrows, capped by a growth factor and by every sampled pose of d staying inside, so enlarging never clips or alters geometry.
- Hoạt động 2 framed 3D views draw the d/M/A/B names as HTML labels with the (α) label's class, projected each frame from pure nameAnchors (geometry.ts; also fed to the framing) after refreshing the camera matrix: parallel d sits a fixed height above its end, M keeps one world offset, contained d sits past its end along d while that line only swings within ±CONTAINED_SWING, so names never touch or hide behind the line or A/B.
- Gemini failures map Google's own error reason (API_KEY_INVALID, *_BLOCKED, SERVICE_DISABLED, location, NOT_FOUND) to a specific teacher message via pure geminiErrorMessage, scrubbing anything key-like, so one generic 'invalid key' never hides the real cause.
- The Gemini call is one shared requestLessonAi; the server relay runs first and only a Google location refusal makes the teacher's browser resend once (Google allows CORS), so a blocked server region never stops the solver.
- Opening a different lesson part scrolls through pure arrivalScrollTop (full screen to the top, otherwise back to the part start only when the page sits below it), so a new part never appears scrolled to its bottom.
- Gửi AI races Gemini against a fallback through pure solveWithSaved (fresh answer wins; error or slow reply shows the fallback and aborts; otherwise a hard timeout); pure fallbackAnswer prefers the teacher's own prepared answer (lesson_ai_prepared, per owner and question, edited behind the Đáp án button hidden by html.presenting) over the class's last fresh solution (lesson_ai_solutions), so a flaky Gemini never blanks a lesson.
